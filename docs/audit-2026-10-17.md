## M2 Performance and frame rate

The laptop that runs at 12–18 fps on its own screen, what the game could show or adapt, a repeatable benchmark, VSync.

**Context**

- The renderer's pixel ratio is min(1, devicePixelRatio) / PIXEL SCALE (src/settings.ts:258, BL-026). RESOLUTION shows CSS pixels, equal to the drawing buffer when DPR ≥ 1.
- Monitor test: 1920×1080 at DPR 1 = 2.07 MP drawn. Laptop test: 2560×1600 at 150% → 1707×1067 CSS = 1.82 MP drawn. Resolution is ruled out.
- Chrome on Windows uses one GPU for everything, the one Windows lists first (the adapter driving the primary display unless Settings → Display → Graphics says High performance). powerPreference: "high-performance" is not honored on Windows.
- This laptop's Intel UHD took 15.6–17.7 ms of GPU at 1280×720 plugged in (BL-029); at 1.82 MP that is ~31–35 ms. The A2000 took 3–7 ms in the playtest. Chrome's Energy Saver caps requestAnimationFrame at 30 Hz.
- No web API turns VSync off. FRAME RATE (Max, 30–144) only limits (main.ts:220-230). The right metric is frame cost: CPU ms and GPU ms, p50/p95/p99, potential fps = 1000 / max(cpu, gpu).

## Test setups

### Two players on one computer

1. Terminal 1: npm run server (the game server on :3000).
2. Terminal 2: npm run dev (:5173), or npm run build && npx vite preview (:4173) for the player build.
3. Window A: open the game, MULTIPLAYER → HOST.
4. Window B: a second window (Ctrl+N), or an incognito window (Ctrl+Shift+N) to get its own name and settings. MULTIPLAYER → JOIN with the code.
5. Put the two windows side by side: a background tab doesn't draw. Each tab is its own player (sessionStorage), so a duplicated tab joins as a second player.
6. Two windows share one GPU: never judge performance this way.

### A weak or dead link for one player (same computer)

1. Terminal 3, in the repo: node, then in the prompt:
2. `const { linkProxy } = await import('./scripts/link-proxy.mjs'); const p = linkProxy(3100, 3000)`
3. Terminal 4: WS_TARGET=ws://localhost:3100 npx vite preview --port 4174 (after npm run build). Window B opens :4174 instead of :4173.
4. In the node prompt: p.down.rate = 8000 (slow downlink, bytes/s) · p.down.rate = 0; p.up.rate = 0 (stall: like Wi-Fi gone) · p.cut() (the link dies now) · p.open() (good network again).
5. Every link B opens goes through the proxy, reconnects included.

### Other devices on the LAN

1. `git worktree add ../roof-next next && cd ../roof-next && npm ci (so other agents' edits don't leak into the build).`
2. `npm run server, then npm run build && npx vite preview --host. Devices open http://<this machine's LAN address>:4173.`
3. Windows may need an inbound firewall rule for WSL on 4173/5173.
4. The pause menu shows the build (v1.3.0-…-g<commit>): check it on every device. Over http there's no clipboard (COPY NETWORK LOG saves a file).
5. MacBook: Safari, Chrome, Firefox; keep it plugged in or turn Energy Saver off (30 Hz cap on battery). Phones can't play (touch only), but work as a hotspot for a weak network.

### Laptop GPU checks

1. Which GPU Chrome uses: chrome://gpu → GL_RENDERER ("ANGLE (Intel…" or "ANGLE (NVIDIA…"). Or Task Manager → Details → add the "GPU engine" column.
2. Force the NVIDIA: Settings → System → Display → Graphics → Google Chrome → High performance, then quit Chrome fully (chrome://restart).

## AUDIT-SYNC format

One line at the very end of an agent's report. The owner pastes it into the workflow page (Sync), which updates statuses, adds the agent's test results (marked "by agent") and the new findings.

```
AUDIT-SYNC {"session":"S3.1","status":"done","findings":{"F3.2":"done","F3.4":"not reproduced"},"tests":[{"test":"T3.2","result":"pass","where":"headless Chromium","notes":"synthetic auxclick"}],"new":[{"id":"F3.16","title":"Short title","what":"What is wrong and where","ev":"src/input.ts:90"}],"note":"one sentence"}
```

- `status`: `done`, `partial` or `blocked` (the session).
- `findings`: id → a status word from above.
- `tests`: what the agent ran; `test` is a T id or a short name.
- `new`: findings the agent added to this file (same ids).
