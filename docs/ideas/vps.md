# Changes for the host (VPS)

What the repo needs from the host, for devops: an item goes here when its repo part lands and leaves once devops reports it done. The host itself: `docs/deploy.md`.

## Waiting

1. **Staging `roof-next` for 1.6.0: its data and admin key.** It has its log files (`LOG_DIR`, its own directory) and protocol 7 since 2026-10-23. With the 1.6.0 server it also gets `DATA_DIR`, `ADMIN_KEY`, `ADMIN_ORIGIN` and `GEOIP_DB`, each its own: its own `/data` directory (never `roof`'s: two servers writing the same saves break them), its own key (`ROOF_NEXT_ADMIN_KEY` in `<apps>/.env`), and `ADMIN_ORIGIN` the admin page's origin (`https://cctv.hidden.haus`). The admin page reaches both servers, `roof` at `/api/main` and `roof-next` at `/api/next` (Caddy adds the key; the page never holds it), so a release is tested end to end on next first.
2. **Kept public sessions and the admin API (1.6.0).** Give `roof` the `DATA_DIR`, `ADMIN_KEY` and `stop_grace_period` of `docs/deploy.md` §6: a directory of its own for `/data`, writable by uid 1000; the key a long random string kept only on the host (e.g. in `<apps>/.env` as `ROOF_ADMIN_KEY`). After the deploy, make the public session once (sessions from then on: `docs/deploy.md` §8): `docker compose exec roof node admin.mjs create public "Hidden Rooftops Session"` (roof, ULTRA, every tool by default). Check: `node admin.mjs list` shows it, and after `docker compose restart roof` it is there again with its paint. Port 3001 stays unpublished; Caddy reaches it later for the admin page.
3. **The GeoIP base (1.6.0).** The players' country on the admin page. Once a month (a cron job or a systemd timer on the host), download DB-IP's free country base, `https://download.db-ip.com/free/dbip-country-lite-YYYY-MM.mmdb.gz` (this month's; CC BY 4.0, about 8 MB), gunzip it to a temporary name in `<apps>/roof/geoip/`, then rename it to `dbip-country-lite.mmdb` (a rename, so the server never reads half a file). Mount the folder read-only and set `GEOIP_DB` as in `docs/deploy.md` §6, for `roof` and `roof-next` (one folder can serve both). The server reads it again within an hour of a change, without a restart. Check: the log says `GeoIP base … <date>` at start, and the admin page shows players' countries.
4. **Web traffic for the admin page (1.6.0).** Caddy writes the game site's access log as JSON to a file (the `log` block in `docs/deploy.md` §6, Traffic: rolled daily, 13 rolled days kept, mode 0644) in a directory of its own, e.g. `<apps>/caddy/logs/access`. Add the `roof-traffic` service of that section: the same image as `roof`, `command: ["node", "traffic.js"]`, that directory mounted read-only, `roof`'s `/data` read-write (uid 1000), the GeoIP folder read-only, `TRAFFIC_HOSTS` set to the game's host. No ports. Check: within a minute of a page load, `<apps>/roof/data/traffic/<today>.json` exists and `views` grows; the admin page's Traffic tab shows it.
