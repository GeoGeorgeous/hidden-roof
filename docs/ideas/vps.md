# Changes for the host (VPS)

What the repo needs from the host, for devops: an item goes here when its repo part lands and leaves once devops reports it done. The host itself: `docs/deploy.md`.

## Waiting

1. **Staging for 1.6.0: `next.roof.hidden.haus`, `roof-next` and the admin page.** All of it is `docs/deploy.md` §9. `next.roof.hidden.haus` serves `next` (a normal `npm ci && npm run build`) through the `roof-next-web` Caddy container. `roof-next` has its log files (`LOG_DIR`) and protocol 7 since 2026-10-23; with the 1.6.0 server it also gets `DATA_DIR` (`./roof-next/data`, never `roof`'s: two servers writing the same saves break them), `ADMIN_KEY` (`${ROOF_NEXT_ADMIN_KEY}` from `<apps>/.env`, mode 600), `ADMIN_ORIGIN` (`https://cctv.hidden.haus`), `GEOIP_DB` (`./roof/geoip`, shared, read-only), `stop_grace_period: 60s` and its own `HOST_MEMORY`, `SNAPSHOT_MEMORY` and `mem_limit` (the host has 7.6 GB shared with other projects). `cctv.hidden.haus` is `import tinyauth` in front of everything, `/api/next/*` to `roof-next:3001` with `header_up Authorization "Bearer {env.ROOF_NEXT_ADMIN_KEY}"` (Caddy needs that variable, so Caddy is recreated, not reloaded) and the rest to `cctv-web`, a small Caddy container serving cctv's `dist/` with the CSP of §9; cctv is built on the host from its read-only deploy-key clone in a throwaway `node:24-slim` container (`npm ci && CCTV_SERVERS=next npm run build`; its own `docs/deploy.md` has the rest). No `/api/main` yet: production runs 1.5.0, which has no admin API. Check: the list at the end of §9.
2. **Kept public sessions and the admin API (1.6.0).** Give `roof` the `DATA_DIR`, `ADMIN_KEY`, `ADMIN_ORIGIN` and `stop_grace_period` of `docs/deploy.md` §6: a directory of its own for `/data`, writable by uid 1000; the key a long random string kept only on the host (e.g. in `<apps>/.env` as `ROOF_ADMIN_KEY`); `ADMIN_ORIGIN` the admin page's origin (without it every POST from the page is answered 403 `origin`, while the GETs work). After the deploy, make the public session once (sessions from then on: `docs/deploy.md` §8): `docker compose exec roof node admin.mjs create public "Hidden Rooftops Session"` (roof, ULTRA, every tool by default). Check: `node admin.mjs list` shows it, and after `docker compose restart roof` it is there again with its paint. Port 3001 stays unpublished; Caddy reaches it later for the admin page (`/api/main`, once prod runs 1.6.0).
3. **The GeoIP base (1.6.0).** The players' country on the admin page. Once a month (a cron job or a systemd timer on the host), download DB-IP's free country base, `https://download.db-ip.com/free/dbip-country-lite-YYYY-MM.mmdb.gz` (this month's; CC BY 4.0, about 8 MB), gunzip it to a temporary name in `<apps>/roof/geoip/`, then rename it to `dbip-country-lite.mmdb` (a rename, so the server never reads half a file). Mount the folder read-only and set `GEOIP_DB` as in `docs/deploy.md` §6, for `roof` and `roof-next` (one folder can serve both). The server reads it again within an hour of a change, without a restart. Check: the log says `GeoIP base … <date>` at start, and the admin page shows players' countries.
4. **Web traffic for the admin page (1.6.0), one reader per game site.** Caddy writes each game site's access log as JSON to a file of its own (a `log` block in the site block, `docs/deploy.md` §6, Traffic: rolled daily, 13 rolled days kept, mode 0644) in a directory of its own, `<apps>/caddy/logs/access` (in the container `/var/log/caddy/access/`): `access.log` for `roof.hidden.haus`, `next-access.log` for `next.roof.hidden.haus`. Add the `roof-traffic` service of that section: the same image as `roof`, `command: ["node", "traffic.js"]`, `CADDY_LOG=/caddy-logs/access.log`, that directory mounted read-only, `roof`'s `/data` read-write (uid 1000), the GeoIP folder read-only, `TRAFFIC_HOSTS` set to the game's host. And its twin `roof-next-traffic`: the `roof-next` image, `CADDY_LOG=/caddy-logs/next-access.log`, `DATA_DIR` `roof-next`'s data, `TRAFFIC_HOSTS=next.roof.hidden.haus`. Each writes into its own server's data, or that server's Traffic tab stays empty. No ports. Check: within a minute of a page load, `<apps>/roof/data/traffic/<today>.json` (staging: `<apps>/roof-next/data/traffic/`) exists and `views` grows; the admin page's Traffic tab shows it.
